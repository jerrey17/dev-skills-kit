# tech-solution-design

基于需求文档生成"技术方案/详设"Markdown 初稿（适用于 TAPD/Wiki 评审），模板来自本 Skill；Java/MySQL 团队规范从 **本地知识库**（路径由 `scripts/kb.config.json` 配置）拉取，与团队线上一致。

## 如何使用

- 提供：需求文档正文（或粘贴文件内容）
- 期望输出：一份 0~8 章齐全、可直接评审且开发可直接编码的技术方案 Markdown

> 如果输入较为零散（脑暴记录、会议纪要等），建议先使用 `requirement-refinement` skill 整理成结构化需求文档，再用本 skill 生成技术方案。

## 工作流概览

1. **输入质量评估** — 判断输入是否充分，决定直接生成还是先追问关键信息
2. **方案选型** — 至少 2 个候选方案对比，给出选择结论
3. **按骨架逐章生成** — 严格对齐 `技术方案模板-骨架.md` 的 0~8 章结构
4. **自检** — 按内置检查清单逐项确认，结果写入文末

## 输出示例（片段）

生成的技术方案 Markdown 结构如下（以支付退款功能为例）：

```markdown

- 方案负责人：张三
- 日期：2026-04-01

- 背景：当前退款流程依赖人工操作...

- 非目标：不涉及部分退款

## 2. 功能点概述
- 功能点 1 **[核心][跨系统]**：退款申请与审批
- 功能点 2 **[核心]**：退款执行与状态流转

（Mermaid erDiagram + DDL + 索引清单）

（状态流转图 + 事务边界 + 并发控制）
...
```

## 与其他 Skill 的协作

| 场景 | 推荐流程 |
|------|---------|
| 输入零散（脑暴/会议纪要） | 先用 `requirement-refinement` 整理为结构化需求 → 再用本 skill 生成技术方案 |
| 跨多系统的大需求 | 先用 `split-requirements-by-system` 按系统拆分 → 再对每个子系统需求分别生成技术方案 |
| 需要独立的接口/DB 设计文档 | 本 skill 生成方案后，可用 `api-db-design-spec` 单独输出接口协议文档和数据库设计文档 |
| 需要 Java 代码模板 | 本 skill 生成方案后，可用 `api-doc-java-alibaba` 生成 REST API 文档和代码骨架 |

## 限制说明

- 本 skill 面向 **Java 后端 + MySQL** 技术栈，不适用于纯前端方案或其他语言栈
- 生成的是**技术方案初稿**，不替代架构评审和团队讨论
- 不生成具体业务代码实现，仅输出设计文档
- 方案中标记 `TBD` 的部分需要人工补齐后方可进入开发

## 引用与依赖（运行时唯一来源）

| 类别 | 来源 | 用途 |
|------|------|------|
| 模板 | `assets/技术方案模板-骨架.md` | 章节骨架 + 写作提示 |
| 模板 | `assets/技术方案-表格模板.md` | 常用表格骨架复用 |
| 示例 | `references/examples/技术方案模板-示例.md` | Mermaid 图、DDL、状态流转图等（按需） |
| 规范 | `call_kb.py` / Read → `kb_root` 下的规范文档 | Java 编码与接口等（**优先 `search` + 关键词**，知识库章号会变；必要时 `read`） |
| 规范 | 同上 → MySQL 建表规范文档 | MySQL 建表/DDL 等（**优先 `search` 关键词**） |
| 规范 | 同上 → 术语与命名规范文档 | 术语与命名（**优先 `search`**） |

团队规范**仅**经 **`scripts/call_kb.py`** 或直接 Read 从本地知识库（`kb_root`）拉取；关键词表见 `SKILL.md`。配置：`scripts/kb.config.example.json`（复制为 `kb.config.json` 并填入 `kb_root`）；`access_mode=remote_mcp` 时额外 `pip install -r scripts/requirements-mcp.txt`。**仅在需要拉取知识库的步骤**执行脚本（见 `SKILL.md`「何时才需执行」）。

**强制**：接口规范、数据库规范、接口字段、路径（URL）命名、数据库字段命名，**必须**以知识库拉取条文为准（见 `SKILL.md`「【强制】知识库为唯一事实来源」）。
