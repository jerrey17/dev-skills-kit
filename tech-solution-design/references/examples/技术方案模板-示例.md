### 流程图示例（6.1.2）

```mermaid
flowchart TD
  A[接收请求] --> B{参数校验}
  B -- 不通过 --> X[返回错误]
  B -- 通过 --> C[幂等校验/去重]
  C -- 命中 --> Y[返回已处理结果]
  C -- 未命中 --> D[落库 INIT]
  D --> E[投递 MQ]
  E --> F{投递成功?}
  F -- 否 --> G[记录失败/触发重试]
  F -- 是 --> H[更新状态 SENDING]
  H --> I[等待回调/消费确认]
  I --> J{确认成功?}
  J -- 否 --> K[补偿/重试/告警]
  J -- 是 --> L[更新状态 SUCCESS]
```

### 时序图示例（6.1.3）

```mermaid
sequenceDiagram
  participant U as 上游/用户
  participant G as 网关/接入层
  participant S as 本服务
  participant MQ as 消息队列
  participant D as DB/缓存

  U->>G: 发送消息请求
  G->>S: 转发请求（含追踪ID）
  S->>D: 记录发送请求（初始状态）
  S->>MQ: 投递消息
  MQ-->>S: 投递结果回调（成功/失败）
  S->>D: 更新消息状态
  S-->>G: 返回处理结果
  G-->>U: 返回响应
```

### 数据库 ER 图示例（5.1.1）

```mermaid
erDiagram
    t_order ||--o{ t_order_item : "包含"
    t_order ||--|| t_payment : "对应"
    t_order {
        bigint id PK "主键ID"
        varchar order_no UK "订单号"
        bigint user_id "用户ID"
        smallint order_status "订单状态: 0-待支付, 1-已支付, 2-已发货, 3-已完成, 4-已取消"
        bigint total_amount "总金额(分)"
        datetime create_time "创建时间"
        datetime update_time "更新时间"
    }
    t_order_item {
        bigint id PK "主键ID"
        bigint order_id FK "订单ID"
        bigint product_id "商品ID"
        int quantity "数量"
        bigint unit_price "单价(分)"
        datetime create_time "创建时间"
    }
    t_payment {
        bigint id PK "主键ID"
        varchar payment_no UK "支付流水号"
        bigint order_id FK "订单ID"
        smallint pay_status "支付状态: 0-待支付, 1-支付中, 2-成功, 3-失败"
        bigint pay_amount "支付金额(分)"
        varchar pay_channel "支付渠道"
        datetime create_time "创建时间"
        datetime update_time "更新时间"
    }
```

> **ER 图绘制要点**：
> - 使用 `||--||`（1:1）、`||--o{`（1:N）、`}o--o{`（M:N）标注关联基数
> - 每个实体列出 PK、FK、UK 和核心业务字段，辅助字段（如 is_deleted）可省略
> - 字段注释写明含义，枚举值写明各取值含义
> - 表名前缀与命名风格以 MCP 拉取的 `mysql_database_specification` 和 `terminology_naming_specification` 为准，本示例仅供格式参考

  `biz_id` VARCHAR(64) NOT NULL COMMENT '业务唯一ID',

### 状态流转图示例（6.1.4）

> 使用 Mermaid `stateDiagram-v2`，每条转移标注格式：`触发事件`。
> 骨架见「技术方案-表格模板.md → 状态流转图」。

#### 单对象示例：退款单状态流转图

```mermaid
stateDiagram-v2
    [*] --> INIT

    INIT --> AUDITING : 提交退款

    AUDITING --> PROCESSING : 审批通过
    AUDITING --> REJECTED : 审批拒绝

    PROCESSING --> SUCCESS : 渠道退款成功
    PROCESSING --> RETRY : 渠道退款失败(可重试)
    PROCESSING --> FAIL : 渠道退款失败(不可重试)

    RETRY --> SUCCESS : 重试成功
    RETRY --> FAIL : 重试耗尽

    SUCCESS --> [*]
    REJECTED --> [*]
    FAIL --> [*]
```

#### 多对象示例：退款场景（订单表 + 退款单表）

> 一个功能点涉及多张表的状态变更时，**每个业务对象画独立的状态流转图**，再用文字说明对象间的联动关系。

**1）订单状态流转图**

```mermaid
stateDiagram-v2
    [*] --> PAID

    PAID --> REFUNDING : 发起退款
    REFUNDING --> PAID : 退款失败
    REFUNDING --> REFUNDED : 退款成功
    REFUNDING --> PARTIAL_REFUNDED : 部分退款成功

    PARTIAL_REFUNDED --> REFUNDING : 再次退款
    PARTIAL_REFUNDED --> [*]
    REFUNDED --> [*]
```

**2）退款单状态流转图**

```mermaid
stateDiagram-v2
    [*] --> INIT

    INIT --> PROCESSING : 提交退款
    PROCESSING --> SUCCESS : 渠道退款成功
    PROCESSING --> FAIL : 渠道退款失败

    SUCCESS --> [*]
    FAIL --> [*]
```

**3）状态联动图**

```mermaid
flowchart LR
    A1["退款单 INIT → PROCESSING"] -->|触发| B1["订单 PAID → REFUNDING"]
    A2["退款单 PROCESSING → SUCCESS"] -->|全额退款| B2["订单 REFUNDING → REFUNDED"]
    A2 -->|部分退款| B3["订单 REFUNDING → PARTIAL_REFUNDED"]
    A3["退款单 PROCESSING → FAIL"] -->|触发| B4["订单 REFUNDING → PAID"]
```

> **状态流转图要点**：
> - 每条转移的标注格式：`触发事件`
> - `[*]` 表示起始/终止伪状态，所有终态指向 `[*]`
> - 未在图中出现的 (当前状态, 触发事件) 组合视为**非法跳转**，运行时应拒绝并告警
> - 状态命名使用全大写下划线（与数据库字段枚举一致）
> - 涉及多个业务对象时，每个对象画独立的状态流转图，再用「状态联动图」（`flowchart`）描述对象间的触发关系

### 灰度方案示例（8.4）

**最小灰度闭环**：

- 小流量时长：10~30 分钟
- 必看指标：成功率、P99 延迟、关键错误码分布、MQ lag/堆积时长（如有）
- 放量条件：所有必看指标连续稳定 15 分钟，且无新增 P1 告警
- 回滚条件：成功率 < 99.9% / P99 > 500ms / MQ lag 持续增长超过 5 分钟 / 资金或核心业务差异 > 0
- 回滚动作：优先止血（关开关/切流量）→ 版本回退 → 数据补偿/修复 → 回滚校验

### 变更高亮示例（Mermaid 图表中标注新增/修改）

> 当方案涉及对已有流程/交互/状态的新增或修改时，使用红色背景高亮本次改动部分。

#### 流程图变更高亮示例（flowchart）

> 场景：已有支付流程中，新增「风控校验」和「异步通知」两个环节。

```mermaid
flowchart TD
  classDef highlight fill:#ffcccc,stroke:#ff0000,stroke-width:2px

  A[接收支付请求] --> B{参数校验}
  B -- 不通过 --> X[返回错误]
  B -- 通过 --> R[风控校验]:::highlight
  R -- 拒绝 --> X2[返回风控拦截]:::highlight
  R -- 通过 --> C[幂等校验/去重]
  C -- 命中 --> Y[返回已处理结果]
  C -- 未命中 --> D[落库 INIT]
  D --> E[调用渠道支付]
  E --> F{支付结果}
  F -- 失败 --> G[更新状态 FAIL]
  F -- 成功 --> H[更新状态 SUCCESS]
  H --> N[异步通知上游]:::highlight
```

> 🔴 红色背景 = 本次新增/修改

#### 时序图变更高亮示例（sequenceDiagram）

> 场景：已有退款流程中，新增「记账服务」调用环节。

```mermaid
sequenceDiagram
  participant U as 上游系统
  participant S as 退款服务
  participant CH as 渠道
  participant D as DB

  U->>S: 发起退款请求
  S->>D: 记录退款单（INIT）
  S->>CH: 调用渠道退款
  CH-->>S: 退款结果回调
  S->>D: 更新退款状态

  rect rgb(255, 204, 204)
    Note over S,AC: 本次新增：退款成功后调用记账服务
    participant AC as 记账服务
    S->>AC: 退款记账请求
    AC-->>S: 记账结果
    S->>D: 更新记账状态
  end

  S-->>U: 退款结果通知
```

> 🔴 红色背景区域 = 本次新增/修改

#### 状态流转图变更高亮示例（stateDiagram-v2）

> 场景：已有退款单状态机中，新增「ACCOUNTING」记账中间态。

```mermaid
stateDiagram-v2
  classDef highlight fill:#ffcccc,stroke:#ff0000,stroke-width:2px

  [*] --> INIT

  INIT --> PROCESSING : 提交退款
  PROCESSING --> SUCCESS : 渠道退款成功，无需记账
  PROCESSING --> ACCOUNTING : 渠道退款成功，需记账
  PROCESSING --> FAIL : 渠道退款失败

  ACCOUNTING --> SUCCESS : 记账完成
  ACCOUNTING --> ACCOUNT_FAIL : 记账失败

  ACCOUNT_FAIL --> ACCOUNTING : 重试记账

  SUCCESS --> [*]
  FAIL --> [*]

  class ACCOUNTING highlight
  class ACCOUNT_FAIL highlight
```

> 🔴 红色背景 = 本次新增/修改

#### 状态联动图变更高亮示例（flowchart）

> 场景：在已有退款联动基础上，新增记账状态联动。

```mermaid
flowchart LR
  classDef highlight fill:#ffcccc,stroke:#ff0000,stroke-width:2px

  A1["退款单 INIT → PROCESSING"] -->|触发| B1["订单 PAID → REFUNDING"]
  A2["退款单 PROCESSING → SUCCESS"] -->|全额退款| B2["订单 REFUNDING → REFUNDED"]
  A3["退款单 PROCESSING → FAIL"] -->|触发| B3["订单 REFUNDING → PAID"]
  A4["退款单 PROCESSING → ACCOUNTING"]:::highlight -->|触发| B4["记账单 INIT → PROCESSING"]:::highlight
  A5["记账单 PROCESSING → SUCCESS"]:::highlight -->|触发| B5["退款单 ACCOUNTING → SUCCESS"]:::highlight
```

> 🔴 红色背景 = 本次新增/修改

---

> **变更高亮要点**：
> - `classDef highlight fill:#ffcccc,stroke:#ff0000,stroke-width:2px` — flowchart / stateDiagram 通用，在图开头定义一次
> - 节点标注：`节点ID[文字]:::highlight`（flowchart）或 `class 状态名 highlight`（stateDiagram，写在图末尾，不能加在 transition 行上）
> - `rect rgb(255, 204, 204)` ... `end` — sequenceDiagram 专用，包裹新增/修改的交互块
> - 每张图下方须有图例行：`> 🔴 红色背景 = 本次新增/修改`
> - **全新功能**（所有节点均为新增）不使用高亮，仅在二次开发/扩展场景下使用
