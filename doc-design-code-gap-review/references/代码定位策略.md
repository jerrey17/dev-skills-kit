# 代码定位策略

目标是在进入事实抽取前，先把代码范围收敛到最小必要集合。

优先定位顺序：

1. 接口入口类
2. 请求 / 响应 DTO
3. 主 service
4. 状态枚举
5. 错误码定义
6. 持久化层
7. 配置类或配置读取点
8. 外部依赖调用点，重点关注 `MeshTemplate` 及其封装层

建议优先使用确定性检索方式：

- URL 路径
- 类名
- 方法名
- DTO 名称
- 字段名
- 枚举名
- 错误码关键字

Java 项目常用收敛点：

- `@RequestMapping`
- `@GetMapping`
- `@PostMapping`
- `@Valid`
- `@Validated`
- `@NotNull`
- `enum`
- `throw`
- `ErrorCode`
- `Mapper`
- `MeshTemplate`
- `meshTemplate`
- `MeshTemplate` 注入字段
- `MeshTemplate` 调用方法
- 基于 `MeshTemplate` 的包装类 / client 类 / 网关类

若项目主要通过 `MeshTemplate` 访问外部依赖，优先顺序建议为：

1. 定位 `MeshTemplate` 的注入位置
2. 定位 `MeshTemplate` 的实际调用点
3. 向上追踪调用它的 service / client / 门面类
4. 再判断这些调用点是否对应需求和技术文档中的外部依赖设计

如果同名实现存在多处，不能直接猜测最终生效路径，应进入 `UNCERTAIN` 或 `NEEDS_CONTEXT`。
