```json
  ],
  "business_rules": [

  ]
}
```

## service-doc-plan

`.service-doc-plan.json` 结构定义（Step 0a 模式判断产出）：

```json
{
  "mode": "multi-service",
  "architecture_overview_file": "workflow/{需求名}/03-技术方案.md",
  "services": [
    {
      "name": "ins-user",
      "role": "主责",
      "output_file": "workflow/{需求名}/03-技术方案-ins-user.md",
      "change_summary": "新增2个接口，修改1个Service",
      "status": "pending"
    }
  ]
}
```

**多服务模式用户展示模板**：

```
📋 检测到多服务模式，将生成以下文档：

架构总览（跨服务视角）：
  03-技术方案.md               ← 背景/端到端时序/完整数据链路/跨服务接口契约/上线顺序

各服务实施方案：
序号 | 服务名     | 角色 | 输出文件
-----|-----------|------|----------------------------------
1    | ins-user  | 主责 | 03-技术方案-ins-user.md
2    | ins-trade | 协同 | 03-技术方案-ins-trade.md

生成顺序：架构总览 → 主责服务 → 协同服务（逐服务确认）
确认后开始生成。
```

```markdown
## 架构约束（从代码推断）
- 分层结构：{如 payorder-api(PB入口+参数校验) → niloan-trade-liquidation(流程引擎)}
- 项目间通信方式：{如内部 RPC / 直接方法调用 / MQ}
- 命名规范：{如类名 XxxService，方法名 doXxx}
- 设计模式：{如策略模式、模板方法等}
- 事务/并发：{如分布式锁使用方式、事务边界}

## 项目级业务约定（从代码扫描，Step 0.5b-3e 产出）

| 约定项 | 数据类型 | 格式规则 | 已有值样例 | 来源符号/文件 |
|--------|---------|---------|-----------|-------------|
| 错误码 | {如 String "100001"} | {如 6位字符串数字，1xx=参数/2xx=业务/9xx=系统} | "100001","200301",... | ErrorCodeEnum.java |
| 交易类型(tradeType) | {如 String "801"} | {如 3位字符串数字} | "101","201","801",... | TradeTypeEnum.java |
| 接口标识(interfaceCode) | {如 String} | {如 UPPER_SNAKE_CASE} | LOAN_TO_PERSONAL, ... | InterfaceEnum.java |
| Proto字段类型约定 | — | {如类型码/状态码统一用string} | trade_type:string, ... | *.proto |
| 可复用数据模型 | — | {如 t_refund_order 已有字段清单} | {已有表/DTO名 + 核心字段列表} | XxxEntity.java / XxxMapper.xml |

> 方案设计中涉及上述约定项时，**必须遵循项目已有格式**，不得自行定义新格式。
> 新增枚举值须避免与已有值冲突。
```

## architecture-overview

架构总览文档内容规格（多服务分档模式，`03-技术方案.md`）：

```
架构总览文档内容（03-技术方案.md）：
  Ch 0  基本信息（版本、TAPD ID、文档说明）
  Ch 1  背景与目标（从 service-split 第二节全局流程提炼，端到端视角）
  Ch 2  功能点清单（从 service-split 第一节直接复用，不重新推导）
  Ch 4  涉及系统（所有服务 + 外部依赖全览，含跨服务调用关系 sequenceDiagram）
  Ch 5  数据库设计（所有服务 DB 变更汇总，包含完整 DDL；个服务文档中注明"见架构总览 Ch 5"）
  Ch 6  跨服务接口契约（新增/修改的跨服务接口的权威定义，含入参/出参/错误码；
         各服务文档 6.x.3 引用此处，不重复定义）
  Ch 7  接口汇总表（所有服务的接口列表）
  Ch 8  上线顺序与整体保障（各服务上线顺序 + 依赖关系 + 整体灰度策略）
  文末  待澄清清单（全局）+ 关键假设
```
