# 证据规则

差异审查按审查对定义证据最小集。

## 1. 审查对与证据最小集

### 需求 -> 技术文档

- 至少需要：需求证据 + 技术文档证据

### 技术文档 -> 代码

- 至少需要：技术文档证据 + 代码证据

### 需求 -> 代码

- 至少需要：需求证据 + 代码证据

### 代码额外实现

- 至少需要：代码证据
- 并且需要明确“当前未在本次基线层中找到对应定义”

## 2. 证据最小要求

每条证据至少包含：

- 文件路径
- 章节位置或行号
- 客观事实描述

## 3. 输出规则

- `需求 -> 技术文档` 阶段不得使用代码证据替代需求证据或技术文档证据
- `技术文档 -> 代码` 阶段不得使用需求证据替代技术文档证据
- `需求 -> 代码` 阶段不得使用技术文档证据替代需求证据或代码证据
- 没有任何可定位证据时，不得输出确定性结论
- 仅存在单边证据时，可记录为待确认线索，但不得直接写入高置信度差异结论

## 4. 建议字段

建议每条差异使用如下结构：

- `gap_id`
- `review_pair`
- `dimension`
- `gap_location`
- `gap_point`
- `severity`
- `confidence`
- `requirement_evidence`
- `design_evidence`
- `code_evidence`
- `conclusion`
- `impact`
- `suggestion`

## 5. 置信度约束

- 低置信度结论不得标记为 `CRITICAL`
- 存在多处同类实现且无法确认真实生效路径时，应标记为 `UNCERTAIN`
- 若某一审查对的大多数结论都缺少双边证据，应在总评中降级为 `NEEDS_CONTEXT`
