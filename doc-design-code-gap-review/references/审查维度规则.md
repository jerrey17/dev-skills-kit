# 审查维度规则

差异审查按“审查对”执行。

审查对是指：

- `需求 -> 技术文档`
- `技术文档 -> 代码`
- `需求 -> 代码`

当模式为 `REQ_DESIGN_CODE` 时，包含两个审查对：

1. 需求 -> 技术文档
2. 技术文档 -> 代码

所有审查对都按以下维度展开：

1. 接口契约
2. 参数校验
3. 状态流转
4. 异常处理
5. 错误码
6. 数据落库 / 表结构影响
7. 配置项
8. 外部依赖调用
9. 兼容性要求

每个维度优先回答：

- 基线层定义了什么
- 对齐层是否完整承接
- 差异发生在哪里
- 差异点是什么

推荐差异落点枚举：

- `API_PATH`
- `CONTROLLER_METHOD`
- `REQUEST_DTO`
- `RESPONSE_DTO`
- `DTO_FIELD`
- `PARAM_VALIDATION`
- `SERVICE_METHOD`
- `SERVICE_BRANCH`
- `STATE_MACHINE`
- `ERROR_CODE`
- `EXCEPTION_HANDLER`
- `CONFIG_KEY`
- `EXTERNAL_CLIENT`
- `DB_TABLE`
- `DB_COLUMN`
- `MAPPER_SQL`

推荐差异类型：

- `REQ_MISSING_IN_DESIGN`
- `REQ_DESIGN_INCONSISTENT`
- `DESIGN_MISSING_IN_CODE`
- `DESIGN_CODE_INCONSISTENT`
- `REQ_MISSING_IN_CODE`
- `REQ_CODE_INCONSISTENT`
- `CODE_EXTRA`
- `PARTIAL_ALIGNMENT`
- `UNCERTAIN`

差异类型使用建议：

- `REQ_MISSING_IN_DESIGN`
  - 基线为需求，对齐层为技术文档
  - 需求有定义，但技术文档未承接

- `REQ_DESIGN_INCONSISTENT`
  - 基线为需求，对齐层为技术文档
  - 技术文档有承接，但内容与需求冲突

- `DESIGN_MISSING_IN_CODE`
  - 基线为技术文档，对齐层为代码
  - 技术文档有定义，但代码未实现

- `DESIGN_CODE_INCONSISTENT`
  - 基线为技术文档，对齐层为代码
  - 代码有实现，但内容与技术文档冲突

- `REQ_MISSING_IN_CODE`
  - 基线为需求，对齐层为代码
  - 需求有定义，但代码未实现或未体现

- `REQ_CODE_INCONSISTENT`
  - 基线为需求，对齐层为代码
  - 代码有实现，但行为或契约与需求冲突

- `CODE_EXTRA`
  - 对齐层为代码
  - 代码存在实现，但在本次基线层中未找到对应定义

- `PARTIAL_ALIGNMENT`
  - 对齐层承接了基线的部分内容，但存在遗漏或条件不完整

- `UNCERTAIN`
  - 证据不足或真实生效路径无法确认，不能输出确定性结论
