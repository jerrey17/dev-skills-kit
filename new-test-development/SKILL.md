# new-test-development — 测试用例生成

## 使用场景

dev-workflow 测试阶段调用。基于以下输入生成测试用例：
- `workflow/{需求名称}/03-技术方案.md` — 接口定义、核心流程
- `workflow/{需求名称}/04-开发编码.md` — 已实现的接口和方法
- 主项目源码（Service 层、Controller 层）

## 输入参数

| 参数 | 说明 |
|------|------|
| 需求名称 | 用于定位产物目录 |
| 主项目路径 | 源码扫描路径 |
| 正式产物目录 | `workflow/{需求名称}/` |

## 执行步骤

### Step 1 — 读取方案和编码产物

读取 `03-技术方案.md` 提取：
- 接口列表（路径、方法、参数、返回值）
- 核心业务流程（正常路径 + 异常分支）
- 数据约束（字段校验规则）

读取 `04-开发编码.md` 提取：
- 已实现的方法列表
- 关键实现说明（边界处理、异常处理）

### Step 2 — 扫描源码

扫描主项目：
- `src/main/java/**/service/` — Service 层方法
- `src/main/java/**/controller/` — Controller 层接口

### Step 3 — 生成测试用例

按以下分类生成：

**单元测试（Service 层）：**
- 正常路径：核心业务逻辑验证
- 边界条件：空值、极值、临界值
- 异常分支：业务异常、系统异常

**集成测试（Controller 层）：**
- 接口联调：完整请求-响应链路
- 参数校验：必填项、格式校验
- 权限校验：无权限、越权访问

### Step 3.5 — 服务联调测试（条件触发）

**触发条件**：测试用例中涉及本地服务启动或服务间接口调用（Feign / Mesh / RPC）时才执行，纯单元测试场景跳过。

执行 `service-integration` skill，路径：`../service-integration/SKILL.md`

联调 skill 会依次处理：
- 联调准备（服务启动检查、外部服务 Mesh 注册、测试数据准备）
- 选择联调模式（服务联调 / 端到端联调）
- 接口契约静态分析 + 测试矩阵生成
- 动态验证（curl 请求 + 日志监控）
- 输出联调报告到 `docs/integration-test-reports/`

联调完成后将报告路径记录到 `06-单元测试.md` 的"三、服务联调结果"节，再进入 Step 4。

---

### Step 4 — 写入产出文件

将测试用例写入 `workflow/{需求名称}/06-单元测试.md`，格式：

```markdown
# 测试用例

## 一、单元测试

### {ServiceName}.{methodName}

| 用例编号 | 场景描述 | 输入 | 预期结果 | 优先级 |
|---------|---------|------|---------|--------|
| TC-001  | 正常创建 | ... | 返回成功 | P0 |
| TC-002  | 参数为空 | null | 抛出 IllegalArgumentException | P0 |

## 二、集成测试

### POST /api/xxx

| 用例编号 | 场景描述 | 请求体 | 预期响应 | 优先级 |
|---------|---------|--------|---------|--------|

## 三、测试执行结果

| 用例编号 | 执行结果 | 备注 |
|---------|---------|------|

## 四、遗留问题

- [ ] {问题描述}
```

文件末尾追加 `## 小结` 段落，3 个固定 bullet（独立调用时也写，作为测试文档小结，非 dev-workflow 专属）：

```markdown
## 小结

- 产出: {文件清单，如 workflow/XX/06-单元测试.md}
- 阻塞: {无，或简述；如"3 个接口未覆盖，需开发补测试桩"}
- 交接: {一句话，下一阶段必须知道的；如"测试用例 50 条覆盖 8 接口，遗留问题 2 个待提测时同步测试同学"}
```

## 产出文件

| 产出物 | 路径 | 步骤 |
|--------|------|------|
| 测试用例文档 | `workflow/{需求名称}/06-单元测试.md` | Step 4 |
| 服务联调报告（条件产出） | `docs/integration-test-reports/{服务名}-{日期}.md` | Step 3.5 |
